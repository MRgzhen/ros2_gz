# 远征 A3 真机部署改动清单

> 适用对象：本工作空间（robot_descriptions / robot_bringup / robot_moveit_config）
> 部署方式：外部 PC 远程控制真机
> 接口依据：智元 AIMA 开放平台 AimDK A3 v3.1 运动控制文档
> <https://open.agibot.com/docs/aimdk/a3/v3_1/dev_guide/07-01-motion_control>

---

## 1. 差距总结：现在缺什么

当前工作空间是**纯 mock 仿真环境**：

- ros2_control 用的是假硬件插件 `mock_components/GenericSystem`（xacro 里官方注释就写着 "This won't work on real hardware"）
- 只配置了右臂 7 关节的控制接口
- 没有任何对接真机的代码（无 SDK、无硬件接口插件）

真机侧（A3 出厂自带运控程序）暴露的是 **ROS2 topic + HTTP JSON RPC**，与 ros2_control 之间缺一层"桥接"。

**好消息：真机的关节命名与你 URDF 里的完全一致**（`right_shoulder_pitch_joint` 等），所以 URDF、SRDF、MoveIt 配置基本不用动。

## 2. 真机接口速查表（官方）

| 用途 | 接口 | 类型 / 消息 | 关键限制 |
|---|---|---|---|
| 手臂控制 | `/motion/control/arm_joint_command` | ROS2 topic，`sensor_msgs/JointState` | **必须填满左右臂 14 关节**；100Hz；相邻指令间隔 <30ms；速度 <4 rad/s；建议低通滤波；仅 MOTION 状态可用 |
| 手臂反馈 | `/motion/control/arm_joint_state` | ROS2 topic，`sensor_msgs/JointState` | 14 关节 position / velocity / effort，无状态限制 |
| 状态机切换 | `http://10.42.10.12:56322/rpc/aimdk.protocol.MotionControlActionService/SetAction` | HTTP JSON RPC | 异步，需配合 GetAction 查询是否完成 |
| 状态机查询 | `.../GetAction` | HTTP JSON RPC | 入参 `{}` |
| 行走控制 | `/motion/control/locomotion_velocity` | `ros2_plugin_proto/msg/RosMsgWrapper` | 仅 MOTION 状态 |
| 腰部控制 | `/motion/control/move_waist` | `RosMsgWrapper` | 需关闭 motion_player |
| 头部控制/反馈 | `/motion/control/neck_joint_command` / `neck_joint_state` | `sensor_msgs/JointState`（head_yaw、head_pitch） | 仅 MOTION 状态 |

**关节顺序（下发时固定）**：
```
left_shoulder_pitch_joint, left_shoulder_roll_joint, left_shoulder_yaw_joint,
left_elbow_joint, left_wrist_roll_joint, left_wrist_pitch_joint, left_wrist_yaw_joint,
right_shoulder_pitch_joint, right_shoulder_roll_joint, right_shoulder_yaw_joint,
right_elbow_joint, right_wrist_roll_joint, right_wrist_pitch_joint, right_wrist_yaw_joint
```

**关节限位（rad，左右对称）**：

| 关节 | 限位 | 关节 | 限位 |
|---|---|---|---|
| shoulder_pitch | ±2.967 | wrist_roll | ±0.576 |
| shoulder_roll | ±1.588 | wrist_pitch | ±1.623 |
| shoulder_yaw | ±2.793 | wrist_yaw | ±2.793 |
| elbow | -1.047 ~ 2.444 | | |

**状态机**：`PASSIVE`（默认）→ `DAMPING` / `PD_STAND`（位控站立，进力控前初始化）→ `MOTION`（可行走、上肢控制）等。程序化切换建议只在力控状态之间进行。

## 3. 必改项（按优先级）

### ① 替换 mock 硬件插件 —— 核心工作量

两处 `mock_components/GenericSystem` 换成自研 A3 硬件桥接：

- `src/robot_descriptions/models/a3_ultra_t2d5/urdf/a3_ultra.ros2_control.xacro`（bringup 实际使用的）
- `src/robot_moveit_config/config/a3_ultra.ros2_control.xacro`（MoveIt demo 使用的）

**推荐方案 A：C++ ros2_control SystemInterface 插件**（新建一个包，如 `a3_hardware`）
- `read()`：订阅 `/motion/control/arm_joint_state`，更新关节状态
- `write()`：以 100Hz 发布 `/motion/control/arm_joint_command`
- 优点：`JointTrajectoryController`、MoveIt 配置**零改动**；控制器本身按 `update_rate: 100` 均匀插值下发，天然满足"100Hz、平滑、<30ms"的要求

xacro 中的插件声明改为：

```xml
<hardware>
  <plugin>a3_hardware/A3System</plugin>
  <param name="arm_command_topic">/motion/control/arm_joint_command</param>
  <param name="arm_state_topic">/motion/control/arm_joint_state</param>
</hardware>
```

插件骨架（`a3_hardware/src/a3_system.cpp`）：

```cpp
#include "hardware_interface/system_interface.hpp"
#include "hardware_interface/types/hardware_interface_return_values.hpp"
#include "rclcpp/rclcpp.hpp"
#include "sensor_msgs/msg/joint_state.hpp"
#include <vector>

namespace a3_hardware {

class A3System : public hardware_interface::SystemInterface {
public:
  RCLCPP_SHARED_PTR_DEFINITIONS(A3System)

  hardware_interface::CallbackReturn on_init(const hardware_interface::HardwareInfo & info) override {
    if (hardware_interface::SystemInterface::on_init(info) !=
        hardware_interface::CallbackReturn::SUCCESS) {
      return hardware_interface::CallbackReturn::ERROR;
    }
    // 从 info_.hardware_parameters 读 topic 名；本插件只声明右臂 7 关节时，
    // joint 数以 info_.journals.size() 为准
    node_ = rclcpp::Node::make_shared("a3_hardware_bridge");
    state_sub_ = node_->create_subscription<sensor_msgs::msg::JointState>(
      arm_state_topic_, rclcpp::SensorDataQoS(),
      [this](sensor_msgs::msg::JointState::SharedPtr msg) { latest_state_ = *msg; });
    cmd_pub_ = node_->create_publisher<sensor_msgs::msg::JointState>(
      arm_command_topic_, 10);
    pos_.resize(info_.journals.size(), 0.0);
    vel_.resize(info_.journals.size(), 0.0);
    eff_.resize(info_.journals.size(), 0.0);
    cmd_.resize(info_.journals.size(), 0.0);
    return hardware_interface::CallbackReturn::SUCCESS;
  }

  hardware_interface::CallbackReturn on_activate(const rclcpp_lifecycle::State &) override {
    // 等待 /motion/control/arm_joint_state 第一帧，用当前状态初始化 cmd_，
    // 防止激活瞬间从 0 跳变
    return hardware_interface::CallbackReturn::SUCCESS;
  }

  std::vector<hardware_interface::StateInterface> export_state_interfaces() override {
    std::vector<hardware_interface::StateInterface> ifs;
    for (size_t i = 0; i < info_.journals.size(); ++i) {
      ifs.emplace_back(info_.journals[i].name, hardware_interface::HW_IF_POSITION, &pos_[i]);
      ifs.emplace_back(info_.journals[i].name, hardware_interface::HW_IF_VELOCITY, &vel_[i]);
      ifs.emplace_back(info_.journals[i].name, hardware_interface::HW_IF_EFFORT, &eff_[i]);
    }
    return ifs;
  }

  std::vector<hardware_interface::CommandInterface> export_command_interfaces() override {
    std::vector<hardware_interface::CommandInterface> ifs;
    for (size_t i = 0; i < info_.journals.size(); ++i)
      ifs.emplace_back(info_.journals[i].name, hardware_interface::HW_IF_POSITION, &cmd_[i]);
    return ifs;
  }

  hardware_interface::return_t read(const rclcpp::Duration &) override {
    rclcpp::spin_some(node_);  // 取 latest_state_，按关节名映射填 pos_/vel_/eff_
    return hardware_interface::return_t::OK;
  }

  hardware_interface::return_t write(const rclcpp::Duration &) override {
    // 组 14 关节 JointState：本插件控制的关节用 cmd_（经低通+限位钳位），
    // 未控制的关节（如左臂）用 latest_state_ 原样回填；velocity/effort 置 0.0
    // cmd_pub_->publish(msg);   —— 由 controller_manager 以 100Hz 调用，满足 10ms 周期
    return hardware_interface::return_t::OK;
  }

private:
  rclcpp::Node::SharedPtr node_;
  rclcpp::Subscription<sensor_msgs::msg::JointState>::SharedPtr state_sub_;
  rclcpp::Publisher<sensor_msgs::msg::JointState>::SharedPtr cmd_pub_;
  sensor_msgs::msg::JointState latest_state_;
  std::vector<double> cmd_, pos_, vel_, eff_;
  std::string arm_command_topic_ = "/motion/control/arm_joint_command";
  std::string arm_state_topic_ = "/motion/control/arm_joint_state";
};

}  // namespace a3_hardware

#include "pluginlib/class_list_macros.hpp"
PLUGINLIB_EXPORT_CLASS(a3_hardware::A3System, hardware_interface::SystemInterface)
```

配套：`plugin.xml`（pluginlib 导出）+ `CMakeLists.txt`（`pluginlib_export_plugin_description_file(hardware_interface plugin.xml)`）。

**备选方案 B：Python 桥接节点**（不想写 C++ 时）
- 去掉 ros2_control，写一个 `FollowJointTrajectory` action server，接收 MoveIt 轨迹后自己插值，以 100Hz 发 `JointState` 到真机，同时把 `/motion/control/arm_joint_state` 转发到 `/joint_states` 给 RViz
- 代价：要自己实现轨迹插值、限速、平滑，安全性不如方案 A

### ② 14 关节补齐（真机硬性要求）

`/motion/control/arm_joint_command` **必须同时填 14 个关节**。当前只控右臂 7 个，所以桥接层 `write()` 里：

- 右臂 7 关节：来自控制器的位置命令
- **左臂 7 关节：从 `/motion/control/arm_joint_state` 回读原样回填**（保持不动）

若以后要双臂控制：把 ros2_control xacro 扩到 14 关节，加 `left_arm_controller`，SRDF 加 `left_arm` 组重新跑 MoveIt Setup Assistant。

### ③ 状态机管理脚本（新增，如 `robot_bringup/scripts/a3_state.py`）

控制真机前必须切到 `MOTION` 状态，流程：

```
GetAction 查询当前状态 → SetAction(PD_STAND) 等到位控站立 → SetAction(MOTION) → 开始控制
```

```python
import requests, time

RPC = "http://10.42.10.12:56322/rpc/aimdk.protocol.MotionControlActionService"

def set_action(ext: str):
    now = time.time()
    body = {
        "header": {
            "timestamp": {"seconds": int(now), "nanos": int((now % 1) * 1e9),
                          "ms_since_epoch": int(now * 1000)},
            "control_source": "ControlSource_SAFE",
        },
        "command": {"action": f"MotionControlAction_{ext}", "ext_action": ext},
    }
    r = requests.post(f"{RPC}/SetAction", json=body, timeout=5)
    r.raise_for_status()

def get_action():
    return requests.post(f"{RPC}/GetAction", json={}, timeout=5).json()

# 上电：set_action("PD_STAND") → 轮询 get_action() 确认 → set_action("MOTION")
# 退出/急停：set_action("DAMPING")
```

退出程序时务必挂 atexit/信号处理器切回 `DAMPING`，避免手臂悬停在力控状态。

### ④ 关闭 motion_player（部署步骤，不改代码）

机器人上 motion_player 会持续占用关节命令通道，**不关则你的命令无效**。ssh 到机器人上执行：

```bash
curl -i -H 'content-type:application/json' -X POST 'http://127.0.0.1:50080/json/stop_app' \
  -d '{"app_name": "motion_player"}'

# 恢复：
# curl -i -H 'content-type:application/json' -X POST 'http://127.0.0.1:50080/json/start_app' \
#   -d '{"app_name": "motion_player"}'
```

注意：关闭后资源管理模块里的预置动作无法播放。

### ⑤ 安全约束（桥接层 + 配置）

- **频率**：controller_manager `update_rate: 100` 已与真机推荐一致，桥接层保证每个周期都 publish（间隔 10ms < 30ms）
- **限速 4 rad/s**：检查 `src/robot_moveit_config/config/joint_limits.yaml`，给 7 个关节设 `has_velocity_limits: true` + `max_velocity` ≤ 4.0，让轨迹规划阶段就受限
- **限位钳位**：桥接层 `write()` 里按第 2 节限位表对命令钳位（`std::clamp`）
- **低通滤波**：`y(k) = (1-a)*y(k-1) + a*x(k)`，a 从 0.3 起调，真机有抖动就调小
- **激活初始化**：`on_activate` 用当前反馈值初始化命令，防止从 0 位突变

### ⑥ launch 参数化（小改）

`src/robot_bringup/launch/robot.launch.xml`：加 `mock`（或 `use_sim`）参数，默认 true 走现在的 mock 流程；真机模式换硬件插件参数、可选保留 RViz 作监控。

## 4. 外部 PC 环境配置

1. **网络**：PC 接入机器人开发网，与运控 IP `10.42.10.12` 同网段（10.42.10.0/24）
2. **ROS2 版本**：与机器人侧一致（装哪版以智元提供的 AimDK 环境说明为准），`ROS_DOMAIN_ID` 两边对齐，确认 DDS 能互相发现（`ros2 topic list` 能看到 `/motion/control/...` 即通）
3. **消息依赖**：手臂控制/反馈用的是标准 `sensor_msgs/JointState`，**外部 PC 不需要** `ros2_plugin_proto`；只有用到行走（`locomotion_velocity`）或腰部（`move_waist`）的 `RosMsgWrapper` 消息时，才需要从机器人配套环境 source `ros2_plugin_proto` 的 `local_setup.bash`

## 5. 不用改的部分

| 项 | 原因 |
|---|---|
| URDF / mesh / SRDF | 关节命名与真机完全一致 |
| `moveit_controllers.yaml` | FollowJointTrajectory 架构不变，控制器名不变 |
| MoveIt 运动学 / 规划配置 | 与硬件无关 |
| `ros2_controllers.yaml` 的控制器类型 | JointTrajectoryController + position 接口正好匹配真机位控接口 |
| `update_rate: 100` | 与真机推荐频率一致 |

## 6. 上真机前的验证步骤

1. **只读验证**：`ros2 topic echo /motion/control/arm_joint_state`，确认 14 关节名、数值合理
2. **桥接空跑**：桥接层只订阅不发布，核对关节名映射、限位表
3. **小幅测试**：机器人吊起或空旷场地，单关节小幅度（±0.1 rad）轨迹，观察是否抖动，调低通系数 a
4. **急停预案**：现场有人持急停；软件层 `set_action("DAMPING")` 一键回阻尼模式
5. 每次测试前确认 motion_player 已关闭、状态机在 MOTION
